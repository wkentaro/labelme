Fixed a config file that carries both an old polygon-named shortcut and its renamed replacement (such as `edit_polygon` alongside `edit_shape`) triggering the "Unexpected key in config" configuration-error dialog on startup; the polygon -> shape shortcut migration renamed an old key only when the new key was absent, so in the both-present case the stale key survived the migration and the whole config was then rejected in favor of the defaults, discarding every other setting in the file. The stale key is now always dropped, an existing new key still wins, and the discarded binding is logged so it is visible
